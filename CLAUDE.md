## Product

**Billfern**: a premium AI-powered subscription tracker and personal finance app.
**Tagline:** Track smarter. Spend less.
**Platforms:** iOS and Android. iOS is the primary development target.

Eventual features: subscription management, monthly and annual spending summaries,
upcoming renewals, categories, active and paused subscriptions, spending analytics,
renewal notifications, AI savings recommendations, personalized insights and
premium plans.

### Routing

- `AppDestination` (enum) is the single source of truth for tab order, path, label
  and icon. Its order must match the branch order in `app_router.dart`.
- `appRouterProvider` exposes the `GoRouter`. Add auth and onboarding redirects there later.
- Tabs use `NoTransitionPage`. Pushed routes use the theme's Cupertino transition.
- Tapping the active tab again resets it to its root (`goBranch(initialLocation: true)`).

### State

Riverpod for shared state. Keep ephemeral UI state (press, animation, form fields) in
`StatefulWidget`s. Data flows through repositories, so Supabase can be swapped in
without touching widgets.

**Data flow (single source of truth):**

```
dataModeProvider ─┬─ personal → personalSubscriptionRepositoryProvider (sembast, overridden in main)
                  └─ sample   → sampleSubscriptionRepositoryProvider (in-memory demo data)
  → subscriptionRepositoryProvider → subscriptionsProvider (SubscriptionsNotifier) ─┐
preferredCurrencyProvider + exchangeRatesProvider → moneyConverterProvider ──────────┴→ dashboard / list / details providers → widgets
```

### Subscriptions and persistence

- **`subscriptionsProvider`** is a `NotifierProvider` (`SubscriptionsNotifier`) with
  `add`, `update`, `pause`, `resume` and `delete`. Every screen (dashboard, list,
  details and analytics) derives from it, so any change updates everything at
  once. Always mutate through the notifier.
- **`SubscriptionRepository`**: `fetchAll()` (current subscriptions) and
  `fetchEnded()` (removed ones kept for history) are synchronous in-memory
  snapshots, while `save` and `delete` are async and write through. The repository is
  replaceable:
  - `SembastSubscriptionRepository`: one record per subscription, keyed by id, in
    the `subscriptions` store of `<documents>/billfern.db`. It loads once in
    `main`, and corrupt records are skipped and counted.
  - `InMemorySubscriptionRepository`: tests and defaults.
  - `DemoSubscriptionRepository`: sample data.
  - For Supabase, either keep this load-then-cache shape or move the notifier to an
    `AsyncNotifier`.
- **`SubscriptionCodec`**: a versioned map format (`schema: 2`; v2 added
  `priceHistory` and `endedOn`). Money is stored as integer `priceMinor` plus
  `currencyCode`, and dates as ISO calendar dates. Old records decode unchanged, and
  malformed revisions are dropped individually.
- **Migrations** (`SubscriptionDatabase.open`, used by `main`): the sembast database
  version equals `SubscriptionCodec.schemaVersion`. On upgrade, every decodable record
  is rewritten in the current schema. Undecodable records are **left untouched**, so
  user data is never deleted. When changing the schema, bump the version and extend
  `migrate`, and add a test to `subscription_migration_test.dart`.
- **Sample vs personal data** (`DataMode`, persisted under `data_mode`):
  - A fresh install starts in **personal** mode, empty, and shows "Start tracking"
    or "No subscriptions yet" states with "Explore sample data".
  - Sample mode reads an in-memory demo repository. Changes are discarded on
    restart, and a `SampleDataBanner` is always shown.
  - **Adding** a subscription in sample mode switches to personal mode first, so
    demo records are never written to the database.
- **`Subscription` equality is by value** (all fields). Riverpod only notifies when
  `==` changes, so id-only equality would hide edits. Use `id` for identity.
- **History-safe dates:**
  - `startedOn` is when spending starts counting. For new subscriptions it's the day
    they were added, so the history chart isn't invented.
  - `billingAnchor` is a known billing date that renewals are computed from. Edits
    move only this.
  - `pausedOn` and `pauseHistory` (`PausePeriod`s): `isBilledInMonth` counts a month
    when the subscription had started and wasn't paused on the month's last day. So
    pausing removes it from the current month and projections, past months stay, and
    paused months stay excluded after resuming.
  - `priceHistory` (`PriceRevision`s: the terms in force **until** a date). Records the
    price, currency and billing cycle before each change. `SubscriptionsNotifier.update`
    adds one automatically via `revisedFrom`: at most once a day, never before the
    start date, and always taking history from the stored record.
    `monthlyCostForMonth(month)` uses the terms in force on the month's last day.
    **Never apply today's price to earlier months.**
  - `endedOn`: `SubscriptionsNotifier.delete` **archives** a subscription that already
    counted towards an earlier month (`end(today)`). A subscription that started this
    month is deleted outright. Ended subscriptions are excluded from `fetchAll()`,
    lists, renewals, projections, categories and current totals, but still count in
    the months before `endedOn`. `isActive` is false for them. Use `isPaused` and
    `isEnded` rather than reading `status` directly.
  - `subscriptionHistoryProvider` = current plus ended subscriptions. **History
    calculations** (the hero's previous month, the trend chart, year to date) use it.
    Everything else uses `subscriptionsProvider`.
- **`BillingCycle`** is a value type (`count` and `BillingUnit` day, week, month or
  year):
  - Presets are `weekly`, `monthly`, `quarterly` and `yearly`, plus
    `BillingCycle.custom(n, unit)`.
  - Cost equivalents use exact fractions (52 weeks or 365 days a year) with one
    rounding step (`Money.scaleRounded`).
- **`ReminderPreference`** is stored per subscription. Notification scheduling comes
  in a later phase.
- **IDs** come from `subscriptionIdGeneratorProvider` (time plus random). Tests
  override it for stable IDs.

- **Money is `Money`**: integer minor units plus an ISO currency code. Never use
  `double` amounts or bare ints for money. Format only with `CurrencyFormatter.format(money)`.
- **No financial maths in widgets.** All totals, comparisons, category shares,
  history and renewals come from `SpendingCalculator`
  (`features/dashboard/domain/`), exposed through `dashboard_providers.dart`.
  Widgets such as `SpendingSummaryCard` only display values they're given.
- Monthly spending = sum of the converted `monthlyCostForMonth` of subscriptions billed
  that month (`Subscription.isBilledInMonth`: started before month end, not paused on
  its last day, not ended by then). So the hero total, the chart's current bar and the
  category slices always agree.
- **Projected payments:** `SpendingCalculator.projectedPayments(withinDays:)` lists
  every billing date from today to today + N days, both inclusive, using
  `Subscription.billingDatesBetween`. Dates are always computed from the anchor, never
  chained, so 31st and 29 February anchors come back. Paused and ended subscriptions
  are never projected. The dashboard's "This week" chip and Analytics' upcoming
  payments both use it.
- Category percentages use the largest-remainder method and always sum to 100. Beyond
  five categories the tail merges into "Other".
- Yearly mock prices divide evenly by 12. Projected yearly is the sum of converted
  `annualCost` values, so with conversion it can differ from monthly × 12 by a few minor
  units of rounding.
- Mock data is built relative to `today`. Tests use `appTestOverrides` from
  `test/helpers/fixed_clock.dart`: a fixed clock (Tue 24 Nov 2026, 09:00) and an
  en_US device locale, so the display currency is USD.
- AI insights come from `MockSavingsInsightEngine` (local rules, no network) behind
  `savingsInsightEngineProvider`. The UI presents them as a "Smart tip" tagged
  *Sample data*, never as real AI analysis. Swap the provider to integrate OpenAI later.
- Sample data (`buildMockSubscriptions`) is only ever served by
  `DemoSubscriptionRepository`; see Subscriptions and persistence.

### Backend, accounts and sync (Phase 5)

**Offline-first.** sembast is the source of truth. Widgets and providers only ever read
local repositories. Supabase is a sync and backup layer, never a competing data
source, and no local operation waits for the network.

- **Configuration** (`SupabaseConfig.fromEnvironment`): `SUPABASE_URL` and
  `SUPABASE_PUBLISHABLE_KEY` come from `--dart-define-from-file=config/supabase.json`.
  The real file is git-ignored; copy `config/supabase.example.json`. Missing or
  placeholder values, or a failed `Supabase.initialize`, mean **local-only mode**:
  `AuthUnavailable`, `LocalOnlyAuthRepository`, no `SyncRemote`, and nothing crashes.
  Never compile service-role keys, database passwords or admin tokens into the app.
- **Request timeouts** (`core/network/timeout_http_client.dart`): `main` passes
  `TimeoutHttpClient` to `Supabase.initialize`, so every Supabase request (PostgREST,
  Auth, Functions) fails after 15 s without headers or body progress. Neither
  `dart:io` nor Supabase Auth time out on their own, and Auth shares **one** token
  refresh between all requests: a refresh that hung while offline used to block
  every request after reconnecting, so "Retry sync" never recovered. Keep it.
  `SupabaseSyncRemote` also caps each call at 20 s. Regression tests:
  `test/features/sync/sync_reconnect_test.dart`.
- **Identity-scoped storage** (`shared/data/local_store.dart`): one sembast file per
  identity. The guest uses `billfern.db` (unchanged, so existing installs keep their
  data). Each account uses `billfern_account_<userId>.db`.
  - `activeLocalStoreProvider` (`LocalStoreController`) opens the new file before
    swapping, serializes switches, and closes the old file.
    `personalSubscriptionRepositoryProvider` follows it.
  - **Account isolation** follows from this: signing out shows the guest database, and
    another account never sees or uploads someone else's records or pending
    operations. Signing out never deletes data; account files stay isolated and
    hidden until the next sign-in.
- **Authentication** (`features/account/`):
  - `AuthRepository` with `SupabaseAuthRepository` (email **one-time code**:
    `signInWithOtp(shouldCreateUser:)` then `verifyOTP(type: email)`; no deep links,
    `detectSessionInUri: false`), `LocalOnlyAuthRepository`, and fakes in tests.
  - **Codes are 6–10 digits** (`OtpCode`, `isPlausibleCode`); the Supabase project
    currently sends 8. Never hardcode a length or say "6-digit" in copy. Codes stay
    strings (leading zeros kept), `OtpCode.normalize` handles pasted text (spaces,
    hyphens, a whole email line), and the full code goes to `verifyOTP` unchanged.
  - Sessions are stored in `SecureSessionStorage` (`flutter_secure_storage`).
  - `AuthController` (`AuthUnavailable` / `SignedOut(sessionExpired)` / `SignedIn`)
    switches stores on verify, sign-out and expiry. An unexpected `signedOut` event
    means the session expired.
  - Failures are typed (`AuthFailureKind`) with fixed messages. **Never log or display
    tokens, emails from errors, or raw server messages.**
  - Apple and Google sign-in can be added as further methods. Don't claim they work
    until credentials are configured and tested.
- **Outbox** (`SyncStore`, account databases only): `SembastSubscriptionRepository`
  writes each change and its `OutboxOperation` in **one transaction** (through the
  `SubscriptionChangeRecorder`). Operations survive restarts.
  - Unsent operations for the same subscription are merged.
  - Attempted operations are never merged, because they may already be on the server.
  - Rejected operations are **parked**, never discarded.
- **Sync protocol** (`SyncEngine`, `SupabaseSyncRemote`, and the SQL in
  `supabase/migrations/`):
  - `sync_push`: idempotent per `opId` through the `sync_operations` table.
    **Version-checked**: the base version is the last acknowledged or pulled version
    from `sync_versions`; `null` means "must not exist".
  - Deletion is a **tombstone** (`deleted_at`). An outdated edit of a deleted record is
    a conflict, never a resurrection.
  - `sync_pull`: the opaque cursor is `"xid:seq"`, ordered by
    **`(change_xid, server_seq)`** and paginated. It only returns rows whose
    `change_xid` is older than the snapshot `xmin`. Any transaction that can still
    commit has a larger xid, so the cursor can never skip a concurrent write. Never
    order by `server_seq` alone: a transaction that takes its xid early and its
    sequence late can commit a higher sequence first.
  - Pulled pages are applied with their versions and cursor in one transaction via
    `applyRemote`, and **never create operations**. Records with pending operations
    or conflicts are skipped by pulls.
  - Runs are single-flight. A manual run requested during an automatic run runs again
    afterwards.
  - Pushes are FIFO. Transient failures stop the push and back off (5 s doubling,
    capped at 15 min).
  - Triggers: sign-in, local edits (debounced), app resume (`SyncLifecycleObserver`),
    connectivity returning, manual sync or retry, and backoff timers. Manual runs
    ignore backoff and retry parked operations, so "Retry sync" attempts delivery
    immediately. The retry timer uses `clockProvider`, the same clock that stamps
    `nextAttemptAt`.
  - **Connectivity** (`ConnectivitySignal`; `ConnectivityPlusSignal` from `main` only
    when sync is configured; `NoConnectivitySignal` by default and in tests, which
    use `FakeConnectivity`) is a **hint, never proof** that Supabase is reachable:
    - Only an offline → online transition seen by the current `SyncController` build
      counts; it is debounced (`connectivityDebounceProvider`, 3 s) and cancelled if
      the network drops again.
    - It syncs only if there are deliverable (non-parked) operations or the last run
      failed offline, so reconnecting costs no request otherwise.
    - `SyncEngine.expediteRetries` clears backoff delays but keeps attempt counts, so a
      further failure backs off as usual. Parked operations wait for "Retry sync".
    - A run already in flight finishes first; then one fresh run follows (single-flight
      engine, no loops).
    - The listener exists only while signed in with an engine. Guests, local-only
      builds and sample data never listen. Sign-out and identity switches cancel it
      through `ref.onDispose`, and timers are cancelled too.
    - The iOS Simulator may not report Wi-Fi changes (connectivity_plus issue 479), so
      verify on a device; Retry, app resume and backoff still cover it.
  - The display currency syncs **both ways** through `profiles`
    (`ProfileSyncPolicy`, `profile_sync.dart`). Changes are detected against the
    last synced state (stored server `updated_at`, compared for equality only; never
    device clocks). A new device adopts the account currency. If only one side
    changed, that side wins. If both changed, the cloud wins.
- **Conflict strategy:** any version mismatch becomes a `SyncConflict`, unless both
  sides decode to identical data. The user chooses `keepThisDevice` (re-sent with the
  cloud version as base, which also restores tombstones) or `useCloud`. Financial
  data is never overwritten silently. `SyncStatus` never reports success while
  operations or conflicts remain.
- **Guest → account** (`GuestMigrationService`, `ImportGuestDataScreen`):
  - Consent comes first, showing a summary and whether the cloud account already has
    data. Choices are **merge** (union by id) or **keep local only**.
  - Merging copies every field and all history (revisions, pauses, ended records).
    It is idempotent and resumable (skips existing ids), never deduplicates by name,
    and never deletes guest data.
  - The decision is stored in the account's `sync_meta`.
  - Sample data is in memory and never in any database, outbox or upload.
- **Deletion and reset:**
  - `AuthController.deleteAccount` calls the `delete-account` Edge Function. It uses
    the service-role key server-side, validates the JWT, needs a confirmation phrase,
    and cascades through foreign keys to `auth.users`. It then destroys the account's
    local file.
  - `eraseThisDevice` erases the current identity's file. For an account, data is
    downloaded again from the cloud.
  - `DataExportService` builds a portable JSON export (architecture only).
- **Database rules** (SQL):
  - Supabase's **default privileges grant ALL**, including `TRUNCATE` (which RLS
    doesn't cover), to `anon` and `authenticated`. Every table migration must
    `revoke all … from public, anon, authenticated` and then grant the minimum.
  - `subscriptions`, `subscription_revisions` and `sync_operations` are **read-only**
    for clients (RLS select-own).
  - **Writes only through `sync_push`/`sync_pull`**: these are `SECURITY DEFINER`
    with `set search_path = ''`, refuse to run without `auth.uid()`, filter every
    statement by that uid, and never accept a user id from the caller.
  - Helper functions aren't executable by clients. Any new definer function needs
    the same discipline.
  - `profiles` and `payment_records` use owner-only RLS (`USING` plus `WITH CHECK`).
    Clients may only write `source = 'manual'` payments; bank-sourced records must come
    from a trusted server process. Profile timestamps are trigger-assigned (`updated_at`
    is the currency-sync change token).
  - Trigger functions are revoked from clients too.
  - `anon` has no privileges.
  - Relationships use composite keys `(user_id, …)`, so cross-owner references fail.
  - Revisions and sync operations are immutable.
  - Ownership changes are rejected by triggers.
  - Money is `bigint` minor units with a 3-letter code. Calendar data is `date`;
    events are UTC `timestamptz`.
  - Remote ids are the stable client ids. New ones are UUID v4; old `sub_…` ids stay,
    under primary key `(user_id, id)`.
  - Schema changes are **new** files in `supabase/migrations/`. Never edit applied
    migrations, and don't deploy to a production project without the user's approval.

### Analytics (`features/analytics/`)

- **Spending bases** (`SpendingBasis`): **estimated** (history from schedules,
  revisions and pauses), **projected** (future payments of active subscriptions) and
  **confirmed** (recorded payments). Label every figure with a `BasisTag` or caption.
  All history is estimated today.
- **Confirmed payments:** the architecture is in place but there is no feature yet.
  `PaymentRecord` and `PaymentRecordRepository` exist, and
  `paymentRecordRepositoryProvider` returns `NoPaymentRecordRepository`. Trend points
  carry a `confirmed` total, which is zero until records exist.
- **`AnalyticsCalculator`** (pure) is built on `SpendingCalculator.totalForMonth`, so
  it shares the dashboard's maths:
  - `trend(history, today, converter, TrendPeriod)` returns `SpendingTrend`. Points
    have `estimated == null` (**no data**) before `trackingSince` (the earliest
    `startedOn`), never zero.
    - `hasEnoughHistory` needs two months with data.
    - `periodComparison` compares with the preceding equal period only when all of it
      has history.
  - `overview` builds on the dashboard summary, plus a month-over-month comparison
    with no baseline for new users.
  - Also `yearly` (year to date and next 12 months), `upcoming` (7, 30 and 90 days)
    and `categoryMembers` (the subscriptions in a breakdown slice; `null` means
    "Other").
- **`PeriodComparison`** kinds: `noBaseline`, `fromZero`, `increase`, `decrease` and
  `unchanged`. `percent` is `null` without a baseline or against zero, so the UI never
  divides by zero. The wording lives in `AnalyticsCopy`.
- **Categories:** Analytics reuses `categoryBreakdownProvider` unchanged (the same
  slices and percentages as the dashboard).
- **Smart suggestions** (`RuleBasedSuggestionEngine` behind
  `smartSuggestionEngineProvider`) are local rules:
  - duplicate service (same `catalogId` or name)
  - overlapping music, streaming or cloud-storage services (savings assume keeping
    the most expensive one)
  - annual renewals within 60 days (plans billed every six months or less often)
  - the largest subscription (at least 10% of monthly spending, three or more
    subscriptions)

  `SmartSuggestions` totals potential savings, counting each subscription once.
  **Wording rules:** never claim a service is unused or unnecessary (there is no usage
  data), and label suggestions as rule-based, not AI. Tests enforce banned phrases.
- **Providers** (`analytics_providers.dart`):
  - `trendPeriodProvider` (Notifier, default 6 months)
  - `spendingTrendProvider` and `spendingTrendForPeriodProvider` (family)
  - `analyticsOverviewProvider`, `yearlySpendingSummaryProvider`,
    `upcomingPaymentsProvider`, `categoryMembersProvider` (family by category) and
    `smartSuggestionsProvider`
  - `hasAnalyticsDataProvider`

  All derive from `subscriptionsProvider`, `subscriptionHistoryProvider` and
  `moneyConverterProvider`, so edits, pauses, deletions and currency changes update
  Analytics immediately.
- **Screen order** (`AnalyticsScreen`):
  1. Header with `CurrencySelector`
  2. `SampleDataBanner`
  3. `AnalyticsOverviewSection` (with exchange-rate status)
  4. `SpendingTrendChartCard`: period pills, selected month with step buttons, a
     yellow `fl_chart` area with tooltips and a mint selected marker, period summary,
     and an insufficient-history state
  5. `SpendingSummariesCard`
  6. `CategoryBreakdownList` (expandable rows with a `_ProgressRing`)
  7. `UpcomingPaymentsCard` (7, 30 or 90 days)
  8. `SmartSuggestionsSection`

  When there is no data at all, it shows `EmptyStateCard` with "Add subscription" and
  "Explore sample data".
- **Known limitations:** history starts when a subscription is added (there's no
  backfill), ended records can't be erased from the UI yet, and paused subscriptions
  are never projected.

### Multi-currency

- **Each subscription has its own currency** (`Subscription.currencyCode`, required) and
  a price in that currency's minor units (`priceMinor`). Changing the display currency
  never modifies prices.
- **Supported currencies:** `Currency.supported` lists USD, EUR, NOK, GBP, SEK, DKK, CHF,
  CAD and AUD, with curated symbols (`$ € kr £ kr kr CHF CA$ A$`). `Currency.of(code)`
  derives any other ISO 4217 currency (symbol and decimal precision, e.g. JPY has 0)
  from `intl`. To offer a new currency, add it to `supported`, and add a mock rate if
  needed.
- **`Money` never mixes currencies.** `+`, `-`, `compareTo` and `Money.sum` throw
  `CurrencyMismatchError`. Rounding is half away from zero.
- **Conversion** happens only in `CurrencyConverter.convert`. It uses exact `BigInt`
  arithmetic on minor units, rates stored as integer millionths, and a single rounding
  to the target precision. It returns `null` when a rate is missing.
  `MoneyConverter` (from `moneyConverterProvider`) binds the target currency and the
  current rate state.
- **All aggregates** (hero, yearly projection, history chart, categories, due this week,
  savings insight) go through `SpendingCalculator.convertedSum`, which converts each
  subscription and then sums. Subscriptions without a rate are **excluded and
  reported** (`excludedCount`, `missingCurrencies`), never mixed in. Totals with any
  conversion carry `isEstimate`.
- **Rates:** `ExchangeRateSource` (development uses `MockExchangeRateSource`:
  deterministic units-per-USD, **development only**), `ExchangeRateCache` (in memory,
  pre-filled with the mock snapshot in development) and `ExchangeRateRepository`
  produce an `ExchangeRateState`: `RatesAvailable(rates, isStale)` (older than 24 h) or
  `RatesUnavailable`. `exchangeRatesProvider.notifier.refresh()` fetches, and falls back
  to the cache. There is no external API yet; plug one in by overriding
  `exchangeRateSourceProvider` (plus a persistent cache).
- **UI rules:** converted totals show "≈" and a `ConversionNote` ("Estimate · mock
  exchange rates", stale or excluded warnings). Subscription cards and renewals show
  the **original** currency. Recently added rows add an "(≈ converted)" hint.
- **Preference:** `preferredCurrencyProvider` (Notifier) holds the saved choice, or else
  the `suggestedCurrencyProvider` value derived from `deviceLocaleProvider` via
  `LocaleCurrency` (region first, then language; euro-area countries map to EUR;
  fallback USD). It's persisted by `CurrencyPreferenceStore`: `main` creates
  `SharedPreferencesWithCache` and overrides the provider, and the default is in
  memory, so tests stay hermetic. `select(code)` and `useSuggested()` change it.
- **Components:** `CurrencySelector` (pill on the dashboard hero),
  `showCurrencyPicker` (bottom sheet), `CurrencyOptionList` (shared with
  `CurrencyPreferenceScreen` at `/settings/currency`, `AppRoutes.currency`), and
  `ConversionNote`.
- **Number locale:** `CurrencyFormatter.configure(deviceLocale)` runs in `main`, so
  grouping, decimal separator and symbol position follow the device (e.g.
  `199,00 kr` in nb_NO). Tests use `en_US`, and `CurrencyFormatter.reset()` restores
  it. Alphabetic symbols get a non-breaking space ("kr 199.00").
- **Mock data** mixes USD, EUR (Figma) and NOK (Viaplay, Storytel). With an en_US
  device the dashboard shows ≈ $164.35/month.

### Subscription catalog (separate from user subscriptions)

- **Catalog** = known services (`SubscriptionCatalogItem`: id, name, domain, category,
  brand colour, logo path, aliases, popular flag, regions). There are **82 services and
  never any prices**. A **user subscription** (`Subscription`) links to it with an
  optional `catalogId`. Several subscriptions may share a `catalogId` (e.g. personal
  and business accounts), and identity is the subscription `id`.
- **Editing the catalog:** edit `SERVICES` in `tool/catalog/build_catalog.py`, then run
  it against an extracted `simple-icons` npm package (see the script's docstring). It
  rewrites the JSON, the SVGs and `docs/brand-logos.md`. Don't hand-edit those outputs.
- `AssetSubscriptionCatalogRepository` loads the JSON and drops logo paths missing
  from the asset manifest. `subscriptionCatalogProvider` (a `FutureProvider`) loads it once.
- **Search:** `SubscriptionCatalog.search(query, category:)` matches names, aliases and
  domains, ignoring case, accents and punctuation ("+" matches "plus"). Ranking is
  exact, then prefix, word prefix, alias and substring. Empty queries return popular
  services. Providers: `catalogQueryProvider` (Notifier: text and category),
  `catalogSearchResultsProvider`, `popularCatalogItemsProvider`.
- **Add and edit flow** (`features/subscriptions/`):
  - **Screens:** `AddSubscriptionScreen` (search, popular grid, category pills,
    "Create custom subscription") leads to `SubscriptionFormScreen` (`.catalog`,
    `.custom` or `.edit`), then to `SubscriptionDetailsScreen`.
  - **Routes:** `/subscriptions/add`, `/subscriptions/add/custom`,
    `/subscriptions/add/service/:catalogId`, `/subscriptions/:id` and
    `/subscriptions/:id/edit`. Add and edit open on the **root navigator**, above the
    floating nav, while details stay in the tab. Use the `AppRoutes` helpers.
  - **`SubscriptionDraft`** holds the form state:
    - `fromCatalog(item, currencyCode:)` pre-fills name, category and catalog link
      (and so the logo and brand colour).
    - The currency starts as the display currency and can be overridden.
    - `validate(today:)` returns `DraftField` errors: name required (≤ 60),
      amount > 0, renewal today or later, valid website domain, notes ≤ 500.
    - `toSubscription(existing:)` keeps identity, status and history when editing.
  - **`MoneyParser`** parses typed amounts into exact minor units. It accepts `.`
    or `,` decimals, grouping and currency precision. A three-digit tail is
    treated as grouping, and the form shows a live formatted preview so mistakes
    are visible.
  - **List:** `SubscriptionListQuery` (`features/subscriptions/domain/`) is pure
    search, filter and sort logic. Price sorting uses the converted monthly
    equivalent, with unconvertible subscriptions last.
- `catalogSearchResultsProvider` is **synchronous** over the loaded catalog
  (`AsyncValue` only while the asset first loads), so typing never flashes a
  loading state.

- **Always render logos through `SubscriptionLogo`** (or `UserSubscriptionLogo` /

- **Resolution** (`SubscriptionLogoResolver`): bundled SVG → bundled raster → remote
  provider (`RemoteLogoProvider`, currently `NoRemoteLogoProvider`, so the app stays

clean white cards, large radii, subtle shadows, bold figures, generous whitespace
and a floating pill navigation. **No default Material look.**

**Never hardcode design values in widgets.** Import `core/theme/theme.dart` and use tokens.
Add a token if one is missing. Brand colours inside mock data are the only exception.

### Accessibility rules

- Keep text contrast at WCAG AA or better. Never put white text on yellow or mint, and
  don't use mint or `danger` for small text on light backgrounds; use the `*Strong` variants instead.
- Touch targets must be at least 48 px (`AppSizes.minTapTarget`).
- Give custom tappables `Semantics(button: true, label: …)`. Mark decorative visuals with `ExcludeSemantics`.
- Mark section titles with `Semantics(header: true)`.
- Use `container: true` on any `Semantics` that must be its own node (buttons, headers,
  list rows). Without it, the annotation merges into the enclosing list item, so a
  whole section is read as one blob and flagged as a button.
- Give money figures a plain semantics label, e.g. `$248.97`.

### Typography gotcha

`google_fonts` registers a separate font family per weight. **Never change `fontWeight`
with `copyWith` on an `AppTypography` style**, because that synthesizes a fake weight.
Add a new token instead. Changing `color` or `fontSize` is fine.

## Coding conventions

- Null-safe, strongly typed code. Use `const` constructors wherever possible.
- Keep files and widgets small. Extract private `_Widget` classes rather than helper methods that return widgets.
- Use `abstract final class` for token and utility namespaces.
- Use enums with fields for variants (`ButtonSize`, `SubscriptionLogoSize`, `AppDestination`).
- Naming: `snake_case.dart` files, `PascalCase` types, `lowerCamelCase` members, and
  `*Screen` for route widgets.
- Avoid deprecated APIs: use `withValues(alpha:)` not `withOpacity`, `*ThemeData`
  classes for component themes, and `isSemantics` in tests.
- Represent money only as `Money`, convert only via `CurrencyConverter`/`MoneyConverter`,
  and format only through `CurrencyFormatter`. Never hardcode currency symbols.
- Never commit secrets or API keys. Future keys belong in `--dart-define` or env config, never in source.
- Don't modify platform folders (`ios/`, `android/`, …) unless the task requires it.

## Development resource constraints

The development machine is a Mac with **8 GB of RAM**. Always follow these rules:

- Run all Flutter commands **sequentially**, never in parallel (no parallel builds,
  tests or analyzers).
- **Shut down simulators before running tests** (`xcrun simctl shutdown all`). Use only
  the existing **Billfern Simulator** for visual review.
- Limit test concurrency to **two workers**: `flutter test --concurrency=2`.
- Monitor memory consumption (`sysctl vm.swapusage`, `top -o mem`) and stop runaway
  processes such as `flutter_tester` immediately. Long or unfamiliar test runs should
  use a memory watchdog that kills the test process above about 1.5 GB.
- Aim for at least **15 GiB** of free storage before iOS builds (`df -h /`).
- Stop resource-intensive tasks (builds, simulators, large test runs) when free
  storage falls below **5 GiB**.
- Don't repeat successful validation (full test suite, iOS build) when implementation
  files haven't changed since it passed.
